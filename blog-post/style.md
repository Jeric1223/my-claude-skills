# 문체 가이드

기준 글: [설치 없이 SQL을 연습할 수 있는 웹 서비스, NULL지마 개발기](https://velog.io/@donghyuk65/%EC%84%A4%EC%B9%98-%EC%97%86%EC%9D%B4-SQL%EC%9D%84-%EC%97%B0%EC%8A%B5%ED%95%A0-%EC%88%98-%EC%9E%88%EB%8A%94-%EC%9B%B9-%EC%84%9C%EB%B9%84%EC%8A%A4-NULL%EC%A7%80%EB%A7%88-%EA%B0%9C%EB%B0%9C%EA%B8%B0)

한 줄 요약: **차분한 합니다체로, 짧은 문장을 한 줄씩 끊어서, 정해진 순서대로 설명한다.** 독자를 놀라게 하려는 글이 아니라 친절하게 안내하는 글이다.

## 어투

- **합니다체로 통일한다.** "~했습니다", "~입니다", "~생각했습니다".
- 해요체, "ㅋㅋ", "..", "~거든요", "~더라고요" 같은 구어체는 쓰지 않는다.
- 감정은 과장하지 않고 생각으로 표현한다. "너무 짜증났다" 대신 "~해야 실력이 는다고 생각했습니다".
- 1인칭은 "제가"를 쓰고 절제한다. 동기를 말하는 도입부와 느낀 점 섹션에서 주로 나온다.

## 문장과 문단

- 문단은 **1~2문장**으로 쓴다. 3문장이 넘으면 나눈다.
- 한 문단 안에서도 **문장마다 줄을 바꾼다.** 긴 문장은 쉼표에서 줄을 바꾼다.

  ```
  특히 SQLD 같은 자격증을 준비할 때도 문법은 공부하지만,
  실제 데이터를 가지고 쿼리를 반복해서 작성해볼 수 있는 환경은 생각보다 부족했습니다.
  ```
- 접속 표현을 반복해서 흐름을 만든다. "하지만 막상", "게다가", "결국", "그래서", "특히", "또한".

## 반복되는 문형

섹션마다 같은 리듬이 돈다. 이 문형은 humanize 단계에서 지우지 않는다.

| 자리 | 문형 |
| :--- | :--- |
| 불편 나열 앞 | "{대상}은 보통 다음과 같은 장벽을 만납니다." |
| 기능 소개 | "{서비스}의 핵심 기능은 **~**입니다." |
| 세부 나열 앞 | "{기능}에는 다음 기능들을 넣었습니다." |
| 섹션 닫기 | "단순히 ~하는 것이 아니라, ~할 수 있도록 만들었습니다." / "~에 초점을 맞췄습니다." |
| 기술 선택 | "이 구조를 선택한 이유는 다음과 같습니다." |
| 회고 | "특히 다음 부분에서 많은 것을 배웠습니다." |
| 계획 | "앞으로는 다음 기능들을 추가해보고 싶습니다." |

불릿 항목은 짧게 쓴다. "~하다.", "~가 필요 없다."처럼 끝내거나 명사로 끝낸다. 불릿 안에서 굵게+콜론 조합은 쓰지 않는다.

## 기술 깊이

- 기술은 **"무엇을 썼고, 그게 뭐고, 그래서 뭐가 가능했는지"** 세 문장이면 충분하다.
- 공식, 상수 튜닝, 파일 경로 같은 구현 디테일은 기본으로 빼둔다. 꼭 필요하면 4장(부딪힌 문제)에 하나만 넣는다.
- 구조는 ASCII 박스·화살표로 된 구조도 하나로 보여준다.

## 시각 요소

- 이모지는 **서비스 링크 줄에만** 쓴다(🌐 🐙). 섹션 제목에는 붙이지 않는다.
- 섹션 제목에는 번호를 붙인다. `## 1.`, `### 2-1.`
- 큰 섹션 사이에는 `---`, 기능 소제목 사이에도 `---`를 넣는다.
- 이미지는 기능 섹션 끝에 둔다. 앞 문장에서 무엇을 하는 화면인지 이미 말했으면 캡션은 생략해도 된다.

## 고쳐 쓴 예

이전 글([루프런](https://velog.io/@hoohoo0889/%ED%86%A0%EC%9D%B4-%ED%94%84%EB%A1%9C%EC%A0%9D%ED%8A%B8-%EB%B0%9C%ED%91%9C-%EC%BD%94%EC%8A%A4-%EC%B6%94%EC%B2%9C-%EC%95%B1%EC%9D%84-%EB%A7%8C%EB%93%A4%EC%97%88%EC%96%B4%EC%9A%94))의 문장을 이 문체로 바꾼 예다.

**도입**

> ❌ 저희 집 근처는 뛰기 좋은 강이나 공원이 없어요.. 시티런이라는거죠
> 집 근처에서 5km만 뛰고 싶은데, 어디로 뛰어야 할지 모르겠더라고요.

> ✅ > "집 근처에서 5km만 뛰고 싶은데, 어디로 뛰어야 할지 모르겠어요."
>
> 러닝을 시작하고 제가 가장 먼저 부딪힌 문제였습니다.
>
> 저희 집 근처에는 뛰기 좋은 강이나 공원이 없습니다.
> 인터넷에 "둔산동 런닝 코스"를 검색해봐도 마땅한 결과가 나오지 않았습니다.

**목표 문장**

> ❌ 그래서 출발점과 거리만 넣으면 돌아오는 코스 3개를 알아서 골라주는 웹앱, 루프런을 만들었어요. 타슈에 이어서 또 제가 불편한 걸 앱으로 만들어버렸네요 ㅋㅋ

> ✅ 그래서 만들게 된 프로젝트가 바로 **루프런**입니다.
>
> **"출발점과 거리만 넣으면, 다시 돌아오는 러닝 코스를 알아서 골라주자."**
>
> 이 목표로 프로젝트를 시작했습니다.

**기술 설명**

> ❌ z13 타일 한 장이 약 3.9km 범위라서 한 장 받아두면 주변 코스를 거의 다 처리할 수 있어요. 캐시 효율이 좋아요.

> ✅ 고도 데이터는 AWS Terrain Tiles를 사용했습니다.
> 지도 타일 이미지의 색상 값에 고도가 담겨 있어, 별도 API 키 없이 고도를 읽을 수 있습니다.
>
> 이 방식을 선택한 이유는 다음과 같습니다.
>
> * API 키와 요청 한도가 없다.
> * 타일 한 장으로 주변 코스를 대부분 처리할 수 있다.
> * 운영비 0원이라는 조건을 지킬 수 있다.

## 이전 글에서 벗어날 습관

- 해요체와 "ㅋㅋ", ".."
- 섹션 제목마다 이모지
- 문단 하나에 3~4문장을 붙여 쓰기
- 공식·코드·상수값을 본문 앞쪽에 배치하기
- 느낀 점, 아쉬운 점, 계획 없이 끝내기
