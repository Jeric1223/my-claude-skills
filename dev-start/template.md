# 정리 보고 골격

7단계에서 이 순서 그대로 쓴다. `<...>`는 실제 값으로 채우고, 해당 없는 섹션은 지우지 말고 "없음"으로 남긴다.

````markdown
## 한 줄 요약
<무엇을 만들었고 지금 어느 상태인지. 예: "API 4개 구현, 타입 체크 통과, 커밋 전">

## 변경 내역
| 구분 | 파일 | 내용 |
|---|---|---|
| 신규 | `<path/file.ts>` | <한 줄> |
| 수정 | `<path/file.ts:라인>` | <한 줄> |

### API
| Method | 경로 | 권한 | 설명 |
|---|---|---|---|
| <GET> | `<경로>` | <역할> | <한 줄> |

### 스키마
<테이블/컬럼 변경, 마이그레이션 파일 경로. 없으면 "없음">

## 검증 결과
- 타입 체크: <명령> → <EXIT=0 / 실패 출력 그대로>
- 마이그레이션 문법: <실행/미실행>
- API 컬렉션 JSON 파싱: <실행/미실행>
- 런타임 호출: <실행/미실행 — 미실행이면 명시>

## 직접 하셔야 할 것
1. **<작업 이름>** — <왜 필요한지 한 줄>
   ```bash
   <복붙 가능한 명령>
   ```
2. **<콘솔 작업>** — <어느 화면> → <무엇을 어떻게 변경>. 롤백: <방법>

## 확인 필요
- <코드로 확인하지 못한 것: 권한 정책, 운영 설정, 다른 환경 차이 등>

## 아직 안 한 것
- 커밋·푸시: <함 / 안 함>
- 통합 브랜치 반영: <함 / 안 함>
````
