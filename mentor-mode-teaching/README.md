# mentor-mode-teaching

Claude가 **사수(시니어)** 역할을 하면서 프로젝트를 같이 진행합니다. 답을 바로 주지 않고, 개념을 먼저 설명한 뒤 "왜 이렇게 해야 할까?"를 물어 예측하게 하고, 답을 들으면 정해진 형식으로 피드백합니다.

## 뭘 하는지

1. 새 기술이나 컴포넌트가 나오면 **개념부터** 설명합니다 (한 줄 정의, 비유, 동작 흐름, 프로젝트 안에서의 역할)
2. 구체적인 시나리오로 **예측 질문**을 1~3개 던집니다
3. 답을 받으면 **✅ 맞은 부분 → 🔧 고칠 부분 → 📖 용어표 → 🎯 면접용 한 문장** 순서로 피드백합니다
4. 모르겠다고 하면 질문을 멈추고 설명한 뒤, **시나리오형이나 빈칸 채우기형**으로 다시 냅니다
5. 정답을 맞히면 실무에서 그 원칙이 조용히 깨지는 지점을 **꼬리 질문**으로 묻습니다
6. 건너뛴 질문은 번호로 추적했다가 관련 단계에서 다시 꺼냅니다

## 왜 이렇게 설계했나

### 요즘은 코드보다 "왜"를 설명하는 능력이 남는다

코드는 AI가 짜는 비중이 커졌습니다. 그러면 포트폴리오에서 남는 건 "왜 이 기술을 골랐고, 안 쓰면 무엇이 터지는가"를 설명하는 능력입니다. 결과물을 받아 적는 것으로는 이게 생기지 않아서, **먼저 예측하고 틀린 부분을 교정받는** 구조로 만들었습니다.

### 모르는 기술을 물어보면 추론이 아니라 막힘이 된다

처음에는 질문부터 던졌습니다. "MQTT 뒤에 왜 Kafka를 또 두나요?"에는 큐라고 짐작해서 답할 수 있었지만, "storage-consumer는 어떤 역할이죠?", "Testcontainers가 정확히 뭘 하죠?"에서는 질문에 답하지 못하고 되묻게 됐습니다. 모르는 것에 대해 예측하라고 하면 학습이 아니라 스트레스가 됩니다.

그래서 **개념 설명을 질문보다 앞에** 두는 규칙을 가장 먼저 못 박았습니다. 비유(Kafka = 지워지지 않는 일지장, 오프셋 = 책갈피)를 넣은 건, 비유가 있어야 사용자가 자기 말로 추론을 시작할 수 있기 때문입니다.

### 결론이 맞아도 이유가 틀렸으면 교정한다

"Kafka 키가 있어야 순서가 보장된다"는 결론은 맞았지만, 이유로 든 "TimescaleDB에 묶어서 저장하기 때문"은 틀렸습니다. "한 건씩 insert하면 커넥션이 초과된다"도 실무의 커넥션 풀을 모르는 데서 나온 오개념이었습니다. 이런 걸 "방향 좋아요"로 넘기면 면접에서 그대로 틀립니다. **좋은 추론과 틀린 사실을 분리해서** 말하도록 피드백 형식에 🔧 칸을 따로 뒀습니다.

### 용어표와 면접용 한 문장

사용자는 개념을 맞게 추론하면서도 용어를 몰라 설명이 길어졌습니다. "한꺼번에 몰리는 걸 중간에서 잠시 담아뒀다가 DB가 감당할 속도로 넣는다"는 **버퍼링**과 **부하 평준화**라는 두 단어로 줄어듭니다. 사용자가 풀어서 한 말과 용어를 나란히 놓는 2열 표, 그리고 그 용어로 압축한 면접용 한 문장을 매번 붙여서 **말을 압축하는 연습**이 되게 했습니다.

### 질문 난이도 사다리

열린 질문에 막히면 같은 내용을 구체적인 시나리오("1~500번을 처리하던 중 죽었다가 재시작하면?")로, 그래도 어려우면 빈칸 채우기로 낮춥니다. 질문을 포기하고 답을 주는 대신 **계단을 낮춰서** 사용자가 스스로 도달하게 합니다.

### 사용자가 쓰기로 한 문서는 껍데기만 만든다

기술 선택 이유(ADR)를 AI가 대신 쓰면 읽고 넘어가게 되고, 결국 사용자 것이 되지 않습니다. 그래서 제목, 날짜, 빈 섹션만 만들고 초안을 받은 뒤에 보강합니다.

## 쓰는 법

```
사수처럼 질문 던지면서 같이 만들어줘
학습용 에이전트 느낌으로 진행해줘
왜 이렇게 해야 하는지 예측하게 해줘
```

진행 기록을 다음 세션까지 이어가려면 [`save-learning-log`](../save-learning-log)와 같이 씁니다.

## 파일

| 파일 | 역할 |
| :--- | :--- |
| `SKILL.md` | 절차: 모드 설정 → 개념 설명 → 예측 질문 → 고정 형식 피드백 → 난이도 낮추기 → 꼬리 질문 → 미답변 추적 |
| `template.md` | 응답 블록: 개념 설명, 질문(시나리오형·빈칸형), 피드백, 대기 중인 항목 |
