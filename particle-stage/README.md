# particle-stage

[knot.kr](https://knoted.kr/) 랜딩처럼 **스크롤 한 번에 장면이 한 장씩 넘어가고, 수천 개의 점이 장면마다 글자·말풍선·파형·그래프로 모이는** 인터랙티브 페이지를 설계하고 구현하는 스킬입니다.

## 뭘 하는지

1. 장면 시나리오(점이 무엇이 되는가 + 캡션 한 문장)를 먼저 잡습니다
2. 장면마다 목적지 좌표를 만드는 방식을 고릅니다 — 픽셀 샘플링 / 수식 / 그래프 / DOM 카드 테두리
3. `template.md`의 `ParticleStage` 엔진을 복사해 장면별 `build()`만 채웁니다
4. 휠·터치·키보드·포인터 입력과 dpr·화면 밖 정지·reduced-motion 처리를 체크리스트로 빠짐없이 넣습니다
5. 데스크톱·모바일·다크모드·reduced-motion에서 각각 확인합니다

## 왜 이렇게 설계했나

### 라이브러리 없이 간다

knot.kr 번들(약 1.2MB)을 실제로 열어보면 GSAP, three.js, Framer Motion, Lenis, Lottie 키워드가 **0건**입니다. 대신 `getContext("2d")`, `requestAnimationFrame`, `devicePixelRatio`, `IntersectionObserver`, `prefers-reduced-motion`이 보입니다. 2D 점 연출은 Canvas 2D + 직접 짠 물리로 충분하고, 그 편이 번들도 가볍고 통제도 쉽습니다.

### 트윈이 아니라 스프링

장면 전환을 "시작 → 끝 보간"으로 만들면 전환 도중 다시 넘길 때 점이 튑니다. 스프링은 언제 목적지가 바뀌어도 현재 속도에서 자연스럽게 방향을 틉니다. 그래서 **장면 전환 = 목적지 배열 교체** 하나로 끝납니다.

### 텍스트는 DOM, 연출은 canvas

캔버스에 글자를 그리면 검색엔진도, 스크린리더도, 복사도 못 합니다. 캡션과 버튼은 DOM으로 두고 canvas는 `pointer-events: none`으로 뒤에 깝니다.

### 엔진은 React 바깥에

수천 개 좌표를 React state로 들면 매 프레임 리렌더가 일어납니다. 엔진은 순수 클래스로 두고 React는 마운트/언마운트만 담당합니다.

### 사용자를 가두지 않는다

스크롤 하이재킹은 첫·마지막 장면 경계에서 반드시 풀어줍니다. 휠은 800ms 잠금으로 트랙패드 한 번에 장면이 끝까지 넘어가는 걸 막습니다.

## 사용 흐름

```
/particle-stage 우리 IoT 관제 서비스 소개 랜딩을 knot처럼 만들어줘. 장면은 센서 → 수집 → 알람 → 대시보드
```

## 검증 상태

세션에서 knot.kr을 분석하고 축소판 데모를 만든 과정에서 추출한 첫 초안입니다. 템플릿 코드는 문법 검사만 했고, RED-GREEN-REFACTOR 압박 시나리오로는 검증하지 않았습니다.
