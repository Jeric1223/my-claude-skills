# qa-check

합동 QA에서 외부 사용자가 실제로 걸리는 지점을 **화면을 직접 열어** 점검하고, QA 시트 한 행 형식으로 이슈를 남기는 스킬입니다.

## 뭘 하는지

1. 이미 로그인된 브라우저 세션으로 점검할 화면 경로를 하나 잡습니다
2. 8가지 "헷갈림 체크리스트"로 화면을 훑습니다
3. QA 댓글이 있으면 지금 사이트에서 재현됨 / 이미 반영된 듯 / 확인 불가 / 의도 확인 필요로 판정합니다
4. `template.md` 형식의 시트 행으로 씁니다
5. 직접 본 화면과 못 본 화면, 판정 개수, 가장 많이 헷갈린 유형을 보고합니다

## 왜 이렇게 설계했나

### 개발자는 "뜻을 몰라서" 생기는 이슈를 못 찾는다

합동 QA 댓글 26건을 보면 버그보다 질문이 더 많습니다. "가동연속성이 뭐죠", "`-%`는 고장인가요", "사유 컬럼의 예약은 무슨 뜻이죠" 같은 것들입니다. 만든 사람은 이미 알고 있어서 스스로 점검하면 놓칩니다. 그래서 외부 사용자가 걸린 패턴을 체크리스트로 고정했습니다.

### 코드가 아니라 화면에서 시작한다

"원래 이렇게 만들었다"는 이슈를 기각할 근거가 안 됩니다. 사용자가 모르면 이슈입니다. 코드는 재현 판정이 끝난 뒤에 따로 봅니다.

### 이미 반영된 것도 판정에 넣는다

QA 시트의 댓글은 며칠 지나면 사이트와 어긋납니다. 오래된 댓글을 그대로 `수정 필요`로 남기면 개발자가 이미 고친 걸 또 고칩니다.

### 비밀번호는 입력하지 않는다

대화에 자격증명이 붙여져 있어도 스킬은 쓰지 않습니다. 로그인된 세션이 없으면 사용자에게 직접 로그인을 요청합니다.

## 사용 흐름

```
/qa-check 대시보드 > 상세 > 우측 패널 화면 점검해줘
```

이 스킬은 `claude-in-chrome`(또는 동등한 브라우저 도구)이 있어야 화면을 볼 수 있습니다.

## 검증 상태

세션에서 추출한 첫 초안이며, RED-GREEN-REFACTOR 압박 시나리오로 검증하지 않았습니다.
