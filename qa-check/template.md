# QA 시트 행 형식

한 행 = 이슈 하나. 열 순서는 시트와 같다.

| 번호 | 화면 경로 | 구분 | 내용 | 참고 | 작성자 | 날짜 |
|------|-----------|------|------|------|--------|------|
| 1 | 메뉴 > 화면 > 패널 > 탭 | 수정 필요 / 확인 필요 | 무엇이 어떻게 보이는지 + 제안 한 가지 | 스크린샷 또는 판정 | 이름 | YYYY.MM.DD |

## 작성 규칙

- **화면 경로**는 `>`로 메뉴부터 탭까지 끝까지 쓴다. "상세 화면" 같은 말은 쓰지 않는다.
- **구분**: 명백한 오류·불일치는 `수정 필요`, 뜻이나 의도를 묻는 건 `확인 필요`.
- **내용**: `[증상]. [제안 한 가지]` 순서. 사실(화면에 보이는 값)과 의견을 문장으로 구분한다.
- **데이터 이슈**는 내용 맨 앞에 `[설비명 / 업체명 / 식별번호]`를 붙인다. 없으면 행을 쓰지 말고 요구한다.
- **참고** 열에는 판정(재현됨 / 이미 반영된 듯 / 확인 불가 / 의도 확인 필요)과 본 화면의 근거를 적는다.

## 예시 (일반화)

| 번호 | 화면 경로 | 구분 | 내용 | 참고 |
|------|-----------|------|------|------|
| 1 | 대시보드 > 상세 > 우측 패널 > 요약 탭 | 확인 필요 | [예시설비 / 예시업체 / 00000] 미지원 항목이 `-%`로 표시되어 고장이나 꺼짐으로 오인될 수 있음. `미지원(N/A)` 표기 제안 | 재현됨 — 요약 카드에서 `-%` 확인 |
| 2 | 데이터 > 이벤트 현황 | 확인 필요 | `사유` 컬럼의 값(예약/취소)이 무엇을 뜻하는지 화면에 설명이 없음. 헤더에 툴팁 제안 | 재현됨 — 두 값 모두 확인 |

## 마무리 요약 형식

```
직접 본 화면: N개 (경로 나열)
못 본 화면: N개 (사유)
판정: 재현됨 N / 이미 반영된 듯 N / 확인 불가 N / 의도 확인 필요 N
가장 많이 헷갈린 유형: #2 빈 값의 의미, #3 설명 부재 (예시)
```
