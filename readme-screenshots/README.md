# readme-screenshots

앱을 **실제로 띄워서** 찍은 화면을 README에 붙입니다. 캡처만 하고 끝나는 게 아니라, 파일 저장 규칙과 README 삽입 형식까지 한 스킬로 끝냅니다.

## 뭘 하는지

1. 레포의 라우트를 훑고 **어떤 화면을 넣을지 먼저 물어봅니다**
2. dev 서버를 띄우고, 로그에서 실제 포트를 읽고, 페이지가 로딩을 끝낼 때까지 기다립니다
3. 뷰포트·devicePixelRatio·테마를 고정해서 캡처합니다 (`chrome-devtools` MCP의 `emulate` 사용)
4. 찍은 이미지를 **직접 열어보고** 실명·토큰·사내 데이터가 찍혔는지 검사합니다
5. `docs/<화면>-<테마>.png`로 저장하고, README에 상대경로 + 확대 링크 형태로 삽입합니다

## 왜 이렇게 설계했나

### 캡처 조건을 고정하지 않으면 다음 갱신 때 깨진다

창 크기에 따라가는 캡처는 매번 다른 해상도로 나옵니다. 반년 뒤 UI가 바뀌어 스크린샷만 갈아끼우면, 이미지 비율이 달라져 README 레이아웃이 틀어집니다.

그래서 `resize_page` 대신 `emulate viewport: "1440x900x2"`를 씁니다. 창 크기와 무관하게 같은 픽셀이 나오고, 조건이 문서에 문자열로 남아 다음 사람이 그대로 재현할 수 있습니다.

### `colorScheme`을 호출한 것과 테마가 바뀐 것은 다르다

다크 모드 캡처의 실패는 대부분 여기서 납니다. `prefers-color-scheme`만 보는 앱이면 `emulate colorScheme: "dark"` 한 줄로 끝나지만, `localStorage`나 `<html class="dark">`로 테마를 관리하는 앱(Tailwind 기본 설정이 그렇습니다)에는 아무 영향이 없습니다. 호출은 성공하고 이미지는 라이트 모드로 나옵니다.

절차에 **토글 클릭 → 저장소 직접 세팅** 폴백 사다리를 넣고, 마지막에 **이미지를 열어 눈으로 확인**하는 단계를 못 박았습니다. 도구 호출의 성공을 결과의 성공으로 치지 않습니다.

### 스크린샷은 코드 리뷰를 안 거친다

`.ts` 파일에 사내 테이블 이름이 들어가면 리뷰에서 걸립니다. PNG에 그게 찍혀 있으면 아무도 못 봅니다. 그런데 레포가 공개되면 똑같이 공개되고, 이미지는 git 히스토리에서 지우기가 더 번거롭습니다.

그래서 저장 전에 **검사 항목을 명시적으로 나열**했습니다 — 실명, 이메일, 토큰, 사내 도메인, 티켓 ID, 그리고 의외로 자주 찍히는 `/Users/<이름>/` 경로. 로그인 화면은 시드 계정으로만 찍게 했습니다.

### 절대경로 raw 링크는 포크에서 죽는다

GitHub 웹 에디터로 이미지를 붙이면 `/owner/repo/raw/main/docs/hero.png` 형태가 생깁니다. 지금은 잘 보이지만 레포 이름을 바꾸거나 누가 포크하면 원본 레포를 가리킨 채 남습니다.

`./docs/hero.png` 상대경로는 브랜치, 포크, 로컬 마크다운 뷰어에서 전부 동작합니다. 이미지를 같은 경로 링크로 감싸서 클릭하면 원본을 볼 수 있게 하는 것까지가 한 세트입니다.

### 갱신은 덮어쓰기다

UI가 바뀔 때마다 `hero-v2.png`, `hero-new.png`가 쌓이면 `docs/`만 봐서는 어느 게 현재 화면인지 알 수 없고, README도 매번 고쳐야 합니다. **같은 파일명에 덮어쓰면 마크다운은 손댈 필요가 없습니다.**

### 앱이 안 뜨면 멈춘다

README의 스크린샷은 "설치하면 이렇게 나옵니다"라는 주장입니다. 앱을 못 띄웠는데 디자인 시안이나 예전 이미지로 채우면 그 주장이 거짓이 되고, 검증되지 않았다는 사실이 문서에서 사라집니다. 못 띄운 이유를 보고하고 멈춥니다.

## 쓰는 법

```
README에 스크린샷 넣어줘
화면 캡처해서 문서에 붙여줘
라이트/다크 모드 둘 다 찍어서 README 갱신해줘
UI 바뀌었으니까 스크린샷 다시 찍어줘
```

## 필요한 것

- **`chrome-devtools` MCP** — 캡처에 씁니다. 없으면 설치 안내부터 합니다
- 브라우저에서 뜨는 앱과 dev 실행 스크립트

## 파일

| 파일 | 역할 |
| :--- | :--- |
| `SKILL.md` | 절차 — 화면 합의 → 기동 → 캡처 조건 고정 → 내용 검사 → 저장 → README 삽입 → 검증 |
| `template.md` | README 삽입 형식 — 라이트/다크 쌍, 캡션형, 데스크톱+모바일 표 |
