# save-learning-log

학습 세션을 끝낼 때 **어디까지 배웠고, 숙제가 무엇이고, 다음에 무엇부터 할지**를 프로젝트 레포의 `MEMORY.md`에 남깁니다. 다음 세션에서는 Claude가 이 파일부터 읽고 그 지점부터 이어갑니다.

## 뭘 하는지

1. 대화에서 한 일, Q&A, 새로 배운 개념, 면접용 문장, 숙제, 답하지 않은 질문을 모읍니다
2. `git status`로 현재 브랜치와 커밋 안 된 변경을 **실측**합니다
3. `MEMORY.md` 맨 위에 **📍 다음에 할 일**(현재 위치, 시작 순서, 숙제, 미답변 질문)을 두고, 아래에 날짜별 기록을 최신순으로 쌓습니다
4. 프로젝트 `CLAUDE.md`에 "세션 시작 시 `MEMORY.md`부터 읽기" 규칙을 한 번만 추가합니다
5. 무엇을 적었는지 보고하고, 커밋은 물어본 뒤에만 합니다

## 왜 이렇게 설계했나

### 학습은 세션을 넘어가는데 대화는 넘어가지 않는다

사수 모드로 하루 동안 질문 7개를 주고받고 설계를 확정했지만, 다음 날 새 세션은 그걸 모릅니다. 어떤 질문에 답했고, 무엇을 틀렸고, 숙제가 무엇이었는지 사용자가 다시 설명해야 합니다. 그래서 **레포 안에 파일로** 남기고, `CLAUDE.md`에서 그 파일을 먼저 읽게 연결했습니다.

Claude 개인 메모리가 아니라 레포에 두는 이유는, 사용자도 직접 열어서 복습하고 레포와 함께 다른 기기로 이동하기 때문입니다.

### "다음에 할 일"이 맨 위에 있어야 한다

기록이 쌓이면 파일이 길어집니다. 최신 상태가 맨 아래에 있으면 다음 세션은 긴 기록을 다 읽어야 현재 위치를 압니다. 그래서 **현재 위치 섹션은 매번 통째로 교체**하고, 날짜별 기록은 최신이 위에 오게 했습니다.

### 틀린 답을 그대로 적는다

"한 건씩 insert하면 커넥션이 초과된다"는 틀린 답이었습니다. 이걸 교정된 내용("왕복과 커밋 비용이 병목")으로 바꿔 적으면 깔끔해 보이지만, 무엇을 몰랐고 무엇을 배웠는지가 사라집니다. Q&A 표에 **내 답**과 **교정** 칸을 나란히 둔 이유입니다. 나중에 다시 읽을 때 성장한 지점이 보입니다.

### 미답변 질문은 원문으로

"Q8 남음"만 적어두면 다음 세션은 Q8이 무엇이었는지 재구성할 수 없습니다. 질문 문장을 그대로 남겨야 **같은 질문을 다시 던질 수** 있습니다.

### 상태는 기억이 아니라 명령으로 확인한다

"브랜치를 만들었으니 거기 있겠지"라고 적으면 틀릴 수 있습니다. `git branch --show-current`와 `git status`로 확인한 값만 적습니다. 커밋 안 된 파일 목록은 다음 세션에서 "이거 커밋해야 한다"를 잊지 않게 해줍니다.

## 쓰는 법

```
오늘은 여기까지, 어디까지 배웠는지 기록해둬
오늘 교육 내용이랑 숙제 MEMORY.md에 적어줘
```

다음 세션에서는 해당 프로젝트 폴더에서 Claude를 열기만 하면 `CLAUDE.md` 규칙에 따라 이어갑니다. [`mentor-mode-teaching`](../mentor-mode-teaching)과 같이 쓰도록 만들었습니다.

## 파일

| 파일 | 역할 |
| :--- | :--- |
| `SKILL.md` | 절차: 재료 수집 → 상태 실측 → `MEMORY.md` 작성·갱신 → `CLAUDE.md` 연결 → 보고. 세션 시작 시 이어가기 모드 포함 |
| `template.md` | `MEMORY.md` 골격: 다음에 할 일, 숙제, 미답변 질문, 날짜별 Q&A 표 |
