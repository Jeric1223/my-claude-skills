# Save Learning Log

## Overview

학습형 세션(특히 `mentor-mode-teaching`)이 끝날 때 **어디까지 배웠고 다음에 무엇부터 할지**를 프로젝트 레포 안의 `MEMORY.md`에 남긴다. 다음 세션의 Claude가 이 파일만 읽고 바로 이어갈 수 있어야 한다.

핵심 원칙 다섯 가지:

1. **맨 위는 "📍 다음에 할 일"이다.** 다음 세션이 가장 먼저 읽을 곳이다. 과거 기록은 그 아래에 날짜별로, **최신이 위**로 쌓는다.
2. **파일은 프로젝트 레포 안에 둔다.** Claude 개인 메모리가 아니라 레포 루트의 `MEMORY.md`. 레포와 함께 다른 기기·세션으로 이동하고, 사용자도 직접 열어 본다.
3. **사용자의 답은 있는 그대로 적는다.** 틀린 답을 미화하거나 교정 후 버전으로 바꿔 적지 않는다. "내 답"과 "교정"을 나란히 둬야 성장이 보인다.
4. **다시 물을 수 있게 원문을 남긴다.** 숙제와 미답변 질문은 요약하지 않고 질문 문장 그대로, 번호를 유지해서 적는다.
5. **날짜는 절대 날짜로.** "오늘", "어제"가 아니라 `2026-09-15`. 대화 컨텍스트의 현재 날짜를 쓴다.

## When to Use

- 사용자가 세션을 끝내거나 중단하면서 기록을 요청할 때
- 학습형 세션에서 교육 내용·숙제·미답변 질문이 생긴 뒤 세션이 끝나갈 때 (먼저 제안만 한다)
- **세션 시작 시 이어가기:** 레포에 `MEMORY.md`가 있으면 읽고 "📍 다음에 할 일"부터 진행한다

**Not for:** 코드 변경 이력(그건 git log가 한다), 프로젝트 설계 문서(그건 docs에 둔다), 학습이 없는 일반 작업 세션.

## 절차

### 1. 대화에서 재료를 모은다

이미 컨텍스트에 있는 대화를 기준으로 한다. transcript 파일을 다시 읽지 않는다. 모을 것:

| 항목 | 예 |
| :--- | :--- |
| 한 일 | 기술 스택 결정, 설계 문서 작성, 레포 생성, 외부 체크리스트 체크 |
| Q&A | 질문 번호, 질문 요지, 사용자 답 요약, 교정·보강, 키워드 |
| 새로 배운 도구·개념 | 한두 줄 정의 |
| 면접용 문장 | 피드백에서 나온 🎯 문장들 |
| 숙제 | 사용자가 다음까지 할 것 (파일 경로 포함) |
| 미답변 질문 | 던졌지만 답을 못 받은 질문 **원문** |
| 사용자 선호 변화 | 예: "다음엔 개념 설명부터 해줘" |

### 2. 현재 위치를 실측한다

추측하지 않고 명령으로 확인한다.

```bash
git branch --show-current
git status --short
git log --oneline -3
```

"현재 브랜치", "커밋 안 된 파일", "push 여부"를 적는다.

### 3. `MEMORY.md`를 쓰거나 갱신한다

`template.md`의 골격을 따른다.

- **파일이 없으면:** 새로 만든다.
- **파일이 있으면:**
  - "📍 다음에 할 일" 섹션은 **통째로 교체**한다. 끝난 숙제·답한 질문은 여기서 빠진다.
  - 날짜별 기록은 **맨 위에 새 항목을 추가**한다. 같은 날짜 항목이 이미 있으면 새로 만들지 않고 거기에 합친다.
  - Q 번호는 이전 기록에서 이어간다.

### 4. 다음 세션이 이 파일을 읽게 연결한다

프로젝트 `CLAUDE.md`(없으면 `AGENTS.md` 등 해당 프로젝트의 지시 파일)에 아래 규칙이 없으면 **한 번만** 추가한다.

```markdown
## 세션 시작 시

**`MEMORY.md`를 먼저 읽고 "📍 다음에 할 일"부터 이어간다.** 세션을 끝낼 때는 날짜별 교육 내용·숙제·미답변 질문을 `MEMORY.md`에 갱신한다.
```

사용자 선호 변화(예: 개념 설명을 먼저)가 있었다면 `CLAUDE.md`의 해당 규칙에도 반영하고, `MEMORY.md` "다음에 할 일"의 시작 순서에도 넣는다.

### 5. 보고한다. 커밋은 요청이 있을 때만

- 무엇을 적었는지 섹션 단위로 짧게 요약한다
- **커밋 안 된 변경 목록**을 말하고 "지금 커밋할까요, 숙제와 같이 커밋할까요?"라고 묻는다
- 사용자가 요청하기 전에는 커밋·push하지 않는다

### 이어가기 모드 (세션 시작)

1. `MEMORY.md`를 읽는다
2. "📍 다음에 할 일"의 현재 위치를 한 줄로 알린다
3. 숙제 확인 → 미답변 질문 → 다음 작업 순서로 진행한다
4. 숙제를 안 했으면 탓하지 않고, 그 자리에서 같이 할지 넘어갈지 묻는다

## Common Mistakes

- **최신 상태를 맨 아래에 붙인다** — 다음 세션이 긴 기록을 다 읽어야 현재 위치를 안다. "다음에 할 일"은 항상 맨 위
- **사용자의 틀린 답을 교정된 버전으로 적는다** — "내 답" 칸이 거짓이 되고, 무엇을 배웠는지 사라진다
- **미답변 질문을 "Q8 남음"처럼 번호만 적는다** — 다음 세션에서 질문 내용을 재구성할 수 없다
- **브랜치·커밋 상태를 기억으로 적는다** — `git status`로 확인한다
- **"오늘", "어제" 같은 상대 날짜** — 파일은 몇 주 뒤에 읽힌다
- **`CLAUDE.md` 연결을 빠뜨린다** — 파일이 있어도 다음 세션이 안 읽으면 소용없다
- **같은 날 두 번 저장하면서 날짜 항목을 중복으로 만든다**
- **묻지 않고 커밋·push한다**
